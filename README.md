# VPN-каскад: 3x-ui → L2TP/IPsec → интернет

```
клиенты ──VLESS+Reality──┐
                         ├─▶ сервер №1 (3x-ui + L2TP) ──L2TP/IPsec──▶ сервер №2 (hwdsl2) ──▶ интернет
клиенты ──L2TP/IPsec─────┘
```

Поддерживаются Debian 11+ и Ubuntu 22.04+.

## 1. Сервер №2 (выходной)

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/yansuhanovskiy/2server-vpn-script/main/exit-server.sh)
```

Скрипт ставит [hwdsl2/setup-ipsec-vpn](https://github.com/hwdsl2/setup-ipsec-vpn), IKEv2 не ставит
(чтобы поставить, запустите с `VPN_SKIP_IKEV2=no`). В конце он печатает готовую команду для сервера №1.
Данные доступа сохраняются в `/root/l2tp-exit-credentials.env`.
В файрволе провайдера должны быть открыты **UDP 500 и 4500**.

## 2. Сервер №1 (входной)

Выполните команду, которую напечатал сервер №2:

```bash
VPN_SERVER_IP='1.2.3.4' VPN_IPSEC_PSK='...' VPN_USER='relay' VPN_PASSWORD='...' \
  bash <(curl -fsSL https://raw.githubusercontent.com/yansuhanovskiy/2server-vpn-script/main/entry-server.sh)
```

Что делает скрипт:
1. Настраивает L2TP/IPsec клиент (strongSwan swanctl + xl2tpd) и сервис `l2tp-exit`, который следит за туннелем и переподключает его.
2. Настраивает policy routing: весь исходящий трафик идёт в туннель, а ответы на входящие
   соединения (SSH, клиенты, панель) уходят напрямую, поэтому SSH не отваливается.
3. Ставит 3x-ui (закреплённая версия `v3.8.5`), создаёт inbound VLESS + Reality поверх XHTTP (порт 443).
4. Поднимает L2TP/IPsec сервер для устройств без VLESS-клиента: Windows, macOS, iOS, роутеры.
   Их трафик тоже уходит через сервер №2.
5. Печатает URL панели, логин и пароль, ссылку `vless://`, QR-код и данные L2TP.
   Всё это сохраняется в `/root/vpn-access.txt`.

**SNI (`REALITY_SNI`)** подбирается автоматически. ТСПУ режет Reality с «чужим» SNI вроде www.microsoft.com
на российском IP хостинга, поэтому нужен сайт из той же сети, что и сервер. Сначала скрипт смотрит таблицу
проверенных хостингов (для FirstVDS это `firstvds.ru`), затем сканирует соседние адреса в /24 и ищет сайт
с TLS 1.3, h2 и валидным сертификатом, домен которого указывает ровно на этот адрес. Если ничего не нашлось,
скрипт остановится и попросит указать `REALITY_SNI=домен` вручную. Все остальные шаги к этому моменту уже
выполнены, поэтому повторный запуск проходит быстро.

### Домен и HTTPS (необязательно, но рекомендуется)

Без домена всё работает: ссылка `vless://`, L2TP, панель по IP. Домен нужен для трёх вещей:

- **Подписка по HTTPS.** Happ и многие другие клиенты не принимают подписку по `http://`
  (ошибка «Небезопасная схема HTTP запрещена»). С подпиской клиенты сами подтягивают
  изменения, и переимпортировать ссылку вручную не нужно.
- **Панель по HTTPS.** Без него логин и пароль панели передаются открытым текстом.
- **Настоящий сертификат для Hysteria2** в `test-variants.sh`. Без него в клиенте приходится
  включать «Allow insecure».

#### 1. Получите домен
Подойдёт любой домен или поддомен: у любого регистратора (reg.ru, Namecheap, Cloudflare и т.д.)
или бесплатный поддомен, например на [DuckDNS](https://www.duckdns.org). Удобно завести отдельный
поддомен, например `vpn.example.com`.

#### 2. Направьте его на сервер №1
Создайте у DNS-провайдера **A-запись**: имя `vpn` (или `@` для корня), значение — IP сервера №1.

- **Cloudflare:** выключите проксирование (серое облако, «DNS only»). Иначе домен указывает на
  адреса Cloudflare, и скрипт откажется продолжать.
- **AAAA-запись (IPv6) не нужна:** скрипт выключает IPv6 на сервере.

Проверьте, что запись применилась (обычно это занимает от нескольких минут до часа):

```bash
dig +short vpn.example.com
```

Должен вернуться IP сервера №1. Если `dig` не установлен, используйте `nslookup vpn.example.com`.

#### 3. Откройте порты
В файрволе провайдера сервера №1 откройте:
- **80/tcp.** Let's Encrypt проверяет по нему домен при выдаче и продлении сертификата.
  На сервере порт должен быть свободен, скрипт это проверит.
- **2096/tcp** — порт подписки.

#### 4. Запустите скрипт с `SUB_DOMAIN`
При первой установке добавьте переменную к обычной команде. Если сервер уже настроен, просто
запустите скрипт ещё раз: подключения, ключи и пароли сохранятся, добавится только HTTPS.

```bash
SUB_DOMAIN='vpn.example.com' VPN_SERVER_IP='...' VPN_IPSEC_PSK='...' VPN_USER='...' VPN_PASSWORD='...' \
  bash <(curl -fsSL https://raw.githubusercontent.com/yansuhanovskiy/2server-vpn-script/main/entry-server.sh)
```

Что сделает скрипт:
1. Проверит, что домен указывает на этот сервер.
2. Получит сертификат Let's Encrypt через [acme.sh](https://github.com/acmesh-official/acme.sh)
   и сохранит его в `/root/cert/<домен>/`.
3. Включит HTTPS для панели и подписки.
4. Напечатает ссылку подписки `https://домен:2096/sub/...` и её QR-код. Именно этот QR нужно
   сканировать в Happ. Ссылка и QR сохраняются в `/root/vpn-access.txt`.

Сертификат действует 90 дней. acme.sh продлевает его сам по cron и после продления перезапускает
x-ui, поэтому порт 80 должен оставаться открытым.

#### Если что-то пошло не так
| Сообщение скрипта | Что делать |
|---|---|
| `домен указывает на [...], а не на <IP>` | A-запись ещё не применилась, указывает не туда или включено проксирование Cloudflare. Проверьте через `dig`. |
| `Порт 80 занят` | На сервере работает веб-сервер (nginx, apache). Остановите его или перенесите. |
| `Let's Encrypt не выдал сертификат` | Порт 80 закрыт в файрволе провайдера, либо превышен лимит Let's Encrypt (5 сертификатов на домен в неделю). Скрипт покажет лог acme.sh. |
| Happ не открывает подписку | Проверьте, что порт 2096 открыт, а в Happ добавлена ссылка `https://...`, а не старая `http://...`. |

### L2TP/IPsec для клиентов
Сервер, PSK, логин и пароль печатаются в конце установки. Их можно задать заранее через `L2TP_PSK`,
`L2TP_USER` и `L2TP_PASSWORD`, а отключить L2TP можно через `L2TP_SERVER=0`.

- **Android 12+** больше не поддерживает L2TP, для него используйте ссылку VLESS.
- **Windows** по умолчанию не подключается к L2TP-серверу за NAT. Выполните один раз от администратора
  и перезагрузитесь:
  ```
  reg add HKLM\SYSTEM\CurrentControlSet\Services\PolicyAgent /v AssumeUDPEncapsulationContextOnSendRule /t REG_DWORD /d 2 /f
  ```
- Клиенты получают адреса `192.168.50.10–250`. DNS у них 1.1.1.1/8.8.8.8, и запросы идут через туннель.
- В файрволе провайдера сервера №1 должны быть открыты **UDP 500 и 4500**.

Необязательные переменные: `INBOUND_PORT`, `REALITY_SNI`, `TRANSPORT` (`xhttp`/`tcp`), `XUI_VERSION`,
`XUI_USERNAME`, `XUI_PASSWORD`, `XUI_PANEL_PORT`, `XUI_WEB_BASE_PATH`, `XUI_SSL_MODE` (`none`/`ip`/`domain`),
`L2TP_SERVER`, `L2TP_PSK`, `L2TP_USER`, `L2TP_PASSWORD`, `SUB_DOMAIN`, `WEBUI`, `DNS_SERVERS`, `KILL_SWITCH`, `DISABLE_IPV6`, `SET_DNS`.
Их описание есть в шапке скрипта.

### Что по умолчанию меняется на сервере №1
- **Kill switch** (`KILL_SWITCH=1`): если туннель упал, сервер не выходит в интернет напрямую.
  Входящие соединения и связь с сервером №2 продолжают работать.
- **IPv6 выключен** (`DISABLE_IPV6=1`): туннель работает только по IPv4, и без этого Xray мог бы ходить по IPv6 в обход туннеля.
- **DNS** (`SET_DNS=1`): `/etc/resolv.conf` указывает на 1.1.1.1/8.8.8.8, запросы идут через туннель.
  Оригинал сохраняется в `/etc/resolv.conf.l2tp-exit.bak`.

### Веб-интерфейс туннеля
Скрипт ставит на сервер №1 небольшой веб-интерфейс (адрес печатается в конце установки,
`https://<IP или домен>:<порт>/`). Вход — пользователь **root** и его системный пароль,
тот же, что для SSH. Если root входит только по ключу, задайте пароль командой `passwd`.

В интерфейсе можно:
- **Видеть состояние:** работает ли туннель, внешний IP, сколько L2TP-клиентов подключено.
- **Менять сервер №2:** IP, PSK, логин и пароль. Туннель переподключится сам. Если данные
  неверны, интерфейс останется доступен и их можно будет исправить.
- **Выбрать поведение при падении туннеля:**
  - *Блокировать всё* (по умолчанию): клиенты VLESS и L2TP остаются без интернета, их трафик
    никогда не выйдет с IP сервера №1.
  - *Работать напрямую*: пока туннель лежит, трафик идёт через провайдера сервера №1.
- **Настроить DNS** для L2TP-клиентов и для самого сервера.
- **Переподключить туннель** одной кнопкой.

Защита: только HTTPS (сертификат домена из `SUB_DOMAIN`, иначе самоподписанный), случайный
порт, блокировка IP на 15 минут после 5 неудачных попыток входа, CSRF-токены в формах.
Отключить интерфейс можно через `WEBUI=0` при запуске скрипта.

Все настройки, которые меняет интерфейс, хранятся в `/etc/l2tp-exit/l2tp-exit.env`. При повторном
запуске `entry-server.sh` берёт их оттуда, поэтому переменные `VPN_*` можно не передавать заново.
Из командной строки те же действия выполняются так:

```bash
l2tp-exit apply       # применить изменённый l2tp-exit.env и переподключить туннель
l2tp-exit reconnect   # переподключить туннель
```

### Управление
```bash
l2tp-exit status                              # SA, ppp, правила, внешний IP
journalctl -u l2tp-exit -f                    # лог переподключений
l2tp-exit down && systemctl disable l2tp-exit # выключить туннель и вернуть маршрутизацию
```

### Диагностика
```bash
bash <(curl -fsSL https://raw.githubusercontent.com/yansuhanovskiy/2server-vpn-script/main/check-client.sh)
```
Эта команда проверяет ссылку из `/root/vpn-access.txt` прямо на сервере: временный Xray-клиент подключается
через неё и печатает внешний IP. Если проверка прошла, а на телефоне не работает, проблема в сети клиента (DPI).

### Подбор протокола под провайдера (`test-variants.sh`)

Разные провайдеры блокируют по-разному. Например, домашний интернет может пропускать VLESS,
а мобильный оператор — «замораживать» его после первых килобайт. Этот скрипт создаёт на
сервере №1 сразу несколько тестовых подключений, чтобы проверить на телефоне, что проходит
именно в вашей сети.

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/yansuhanovskiy/2server-vpn-script/main/test-variants.sh)
```

| | Протокол | Порт | Клиент |
|---|---|---|---|
| A | VLESS TCP + Reality + Vision | 8443/tcp | Happ, v2rayNG, Hiddify… |
| B | VLESS XHTTP + Reality | 9443/tcp | Happ, v2rayNG, Hiddify… |
| C | VLESS TCP + Reality + VLESS encryption (ML-KEM) | 10443/tcp | Happ (свежие версии) |
| D | Shadowsocks-2022 | 8388/tcp+udp | Happ, v2rayNG… |
| E | Hysteria2 (QUIC) | 4443/udp | Happ, Hiddify… |
| F | AmneziaWG (WireGuard с обфускацией) | 51820/udp | AmneziaVPN, AmneziaWG |
| G | Hysteria2 + обфускация Salamander | 4444/udp | Happ, Hiddify… |

Для вариантов A–C скрипт печатает ссылки `vless://`. Для D–G ссылку или QR возьмите в панели:
Inbounds → `test-…` → клиент → иконка QR. Панель сама собирает правильную ссылку для каждого
протокола, а у AmneziaWG — конфиг `.conf` и ссылку `vpn://` для приложения AmneziaVPN.

**Как проверять.** Переключитесь на нужную сеть (например, мобильный интернет) и в каждом варианте
откройте несколько сайтов и видео. Одного сайта мало: заморозка наступает после 15–30 КБ, и
на коротком запросе она незаметна. Если вариант держится стабильно, пересоздайте основной
inbound с этими настройками или просто оставьте тестовый.

**Полезно знать:**
- **Защита основного подключения.** Если Xray не принял какой-то вариант, скрипт выводит ошибку,
  удаляет этот вариант и продолжает с остальными. Основное подключение на 443 не пострадает.
- **Повторный запуск** пересоздаёт все тестовые подключения с новыми ключами, поэтому ссылки нужно
  импортировать заново.
- **Hysteria2 (E, G)** использует сертификат домена из `SUB_DOMAIN`, если он настроен. Без него
  сертификат самоподписанный, и в клиенте нужно включить «Allow insecure».
- **SNI для вариантов A–C** по умолчанию `firstvds.ru`. Для другого хостинга задайте свой:
  `SNI=домен bash <(curl ...)`.
- **UDP-протоколы (D–G).** Если у провайдера сервера есть файрвол, откройте в нём эти порты для UDP.
- **Удаление.** Тестовые подключения (`test-*`) удаляются в панели, раздел Inbounds.

**Из опыта на МегаФоне (Москва):** VLESS с отпечатком `chrome` не проходит, потому что ClientHello
с постквантовым ключом не влезает в один пакет. С отпечатком `ios` рукопожатие проходит, но
поток замораживается после ~5 КБ. L2TP/IPsec (UDP) при этом работает, поэтому UDP-варианты
(E, F, G) стоит проверять первыми.
